A logical document ID is independent of its PDF hash. A source URL plus reliable full meeting date is an alias; another URL or changed date with a possible existing match is quarantined. The reviewer-only `GET /api/reviewer/agenda-documents/unresolved` and `POST /api/reviewer/agenda-documents/{id}/resolve` endpoints explicitly link to an existing document or create a separate document ID. The request requires the unresolved observation revision and a reason. It records actor/reason under the canonical lock, then returns `retry_required`; a later verified source run activates the aliased PDF. A stale or conflicting resolution is 409.

The current parser has no authoritative agenda item ID. Its ordinal is only an observation key within one immutable document/extraction revision. First-seen candidates get stable internal IDs; an exact legacy staged ID can be retained when unambiguous. On a changed PDF, unmatched items enter `identity_unresolved` and leave prior decisions and published snapshots untouched. The reviewer-only `GET /api/reviewer/agenda-observations/unresolved` and `POST /api/reviewer/agenda-observations/{id}/resolve` endpoints link the occurrence to an existing candidate or deliberately create a new one, with expected observation/candidate revisions, actor/reason, and a durable audit event. Linking changed content creates a pending content revision. An unchanged replay leaves state revision, notes, actor, decision time, first discovery date, geometry, and publication intact.

Any unresolved document or candidate makes agenda health `degraded` with `agenda_identity_unresolved` and a count. It is never reported as a complete healthy refresh merely because the PDF/text copies were verified.

Agenda review actions carry `expected_revision`; they lock and compare before mutating. A stale action returns `review_revision_conflict` (409). Decision events retain previous status, actor, notes, time, content revision and state revision. Old agenda rows without explicit revision metadata are adopted on exact replay; an existing approved/rejected decision receives a marked legacy baseline event with unknown actor/time if that information was never stored. Existing published IDs are preserved. A rejected new revision does not retract an older public record.

A materially changed revision returns `agenda_publication_update_pending` (409) and stays pending, preserving the old public version.
